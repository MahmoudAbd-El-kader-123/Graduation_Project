# Sprint 3 AI invoice pipeline manual test

This test uses the demo purchase order created by
[`scripts/sql/seed-sprint3-ai-demo.sql`](../scripts/sql/seed-sprint3-ai-demo.sql).
The script can be run repeatedly: it updates the identified vendor, products,
purchase order, and items or inserts them when missing. It rolls back if its
financial checks fail.

## Prerequisites

- SQL Server LocalDB contains the migrated `SPIP_DB` database.
- At least one active row exists in `Users_Domain`.
- The AI workflow accepts invoice files at
  `http://localhost:5678/webhook/d11ede0e-9d6f-4b45-8ba7-bd833c8df652`.
- `SPIP.API/appsettings.Development.json` points both
  `ConnectionStrings:DefaultConnection` and
  `ConnectionStrings:HangfireConnection` to `SPIP_DB`.
- The invoice file matches the JSON fixture documented for this Sprint 3
  workflow.

## 1. Seed the matching purchase order

From the repository root in PowerShell:

```powershell
sqlcmd -S "(localdb)\MSSQLLocalDB" -d SPIP_DB -E -b -f 65001 `
  -i "scripts\sql\seed-sprint3-ai-demo.sql"
```

Expected summary:

```text
ItemCount  Subtotal  Vat     TotalAmount
9          4603.62   690.54  5294.16
```

Use the `PurchaseOrderId` printed by the script for the upload request. On the
current demo database it is `1`, but callers must use the printed value rather
than assume that ID on another database.

## 2. Start the backend

```powershell
dotnet run --project SPIP.API --urls http://localhost:5000
```

Swagger is available at `http://localhost:5000/swagger` in the development
environment.

## 3. Authenticate

In Swagger, call:

```http
POST /api/auth/login
Content-Type: application/json
```

Request:

```json
{
  "email": "admin@spip.com",
  "password": "Admin@123"
}
```

Copy `data.token` from the response. Select **Authorize** in Swagger and enter:

```text
Bearer YOUR_JWT_TOKEN
```

Do not commit a real JWT. It is a short-lived credential.

## 4. Upload the invoice

Call:

```http
POST /api/invoices/upload
Content-Type: multipart/form-data
```

Form fields:

| Field | Value |
|---|---|
| `File` | The matching invoice PDF or supported image file |
| `PurchaseOrderId` | The ID printed by the seed script |

The successful response includes:

```json
{
  "success": true,
  "data": {
    "invoiceId": 1,
    "status": "Queued",
    "fileName": "invoice.pdf"
  }
}
```

The actual invoice ID is generated by the database and may differ.

## 5. Read the processing result

Poll with the ID returned by the upload:

```http
GET /api/invoices/{invoiceId}
Authorization: Bearer YOUR_JWT_TOKEN
```

Processing normally moves through:

```text
Uploaded → Queued → Processing → Extracted → Validated → Compared → Completed
```

For the matching fixture, verify:

```text
data.status                 = "Completed"
data.items.length           = 9
data.subtotal               = 4603.62
data.vat                    = 690.54
data.totalAmount            = 5294.16
data.discrepancies.length   = 0
```

## Failure checks

- `Failed`: inspect `data.processingLogs` for AI transport, JSON, or file
  processing errors. Confirm the AI workflow is running on port `5678`.
- `NeedsReview`: inspect `data.processingLogs` for invoice validation failures.
- `Completed` with discrepancies: inspect `data.discrepancies`. Confirm the
  uploaded invoice belongs to the seeded PO and that the seed command completed
  without an error.
- HTTP `401` or `403`: authenticate again and confirm the user has the required
  invoice permission.

The backend stores the uploaded original file locally. Download it with:

```http
GET /api/invoices/{invoiceId}/download
Authorization: Bearer YOUR_JWT_TOKEN
```
